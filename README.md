# 章序 · 小说连续性检查

一张可爱的小书桌，帮助中文连载作者把新旧章节里的**明确设定和原文证据**放在一起核对。

浏览器本地处理 · 无需模型密钥 · 无第三方运行依赖 · TXT / Markdown / DOCX · 版本 0.1.0

![章序界面：合成样稿中的惯用手差异与成对原文](docs/preview.jpg)

完整流程：导入旧稿 → 提取并确认设定 → 检查新章 → 对照原文判断 → 收录新章并更新设定。

**当前为有限句式的规则验证版，尚未接入 AI 语义审稿。** 内置样稿与用户导入的稿件使用同一个引擎，没有预设检查结果。它无法理解所有小说表达，也尚无真实作者的准确率、节时或付费验证。

## 试用

打开工作台，点击“载入测试样稿”，浏览并确认 12 条候选设定，进入“新章检查”并点击“检查本章”。样稿预期为 3 条明确属性差异、4 条需结合剧情的提示。双侧原文都能定位。

[前文样稿](examples/old-manuscript.txt)和[新章样稿](examples/new-chapter.txt)也可以单独下载。

可为每条差异标记“确有错误”“正常变化”“误报 / 不适用”并记录备注。相同标题、原文语境及设定再次检查时恢复判断；改写或更换设定后重新判断。正文、标题或设定修改后，旧结果会标为需重新检查。

“收录本章”会把新章加入稿件库，并将新增设定放入待确认列表。已标为错误的正文需要先修改、重新检查。正常阵营变化等只有再次确认设定后，才用于下一章。

## 检查边界

支持 12 类明确设定，包含用于统一对象的别名：惯用手、瞳色、血型、生父、生母、出生地、年龄、阵营、生死状态、固定编制、长度、别名。

例如“陆沉的惯用手是左手”“陆沉效忠北境军”“银鸦卫的固定编制为三百人”。代词、隐含关系、多义表达、完整事件时间线及历史事实不在本版覆盖范围。无法匹配到表达时会明确提示识别数量，不将空结果描述为全稿正确。

回忆、对话、传闻、梦境、伪装、明确变化和时间推进通过有限文本线索降低结论强度；仍可能漏识别，需要作者审稿。年龄、阵营和生死状态不同一律交给作者判断。数词支持常见中文 / 阿拉伯数字；长度仅在同一度量体系内转换。

章节顺序按导入、收录顺序排列，不自动推断故事时间。确认后的同一对象、同一属性以最近收录章节为准。回忆中的旧状态不应作为当前设定确认。

每条引用必须通过章节 ID、起止位置和逐字引文校验；错误引用不进入检查。作者也可手动补充有原文依据的设定。

## 文件与存储

- TXT（UTF-8，失败时尝试 GB18030）、Markdown、DOCX。旧版 DOC、扫描图片暂不支持。
- DOCX 提取可编辑正文段落；不保留版式，不含图片文字、页眉页脚或批注。使用浏览器原生解压能力，不下载第三方库。
- 单文件 8 MB；单次导入 150 万字符 / 1500 章；单部作品 300 万字符 / 3000 章；单次新章 10 万字符；最多保存 200 次检查记录。
- 稿件、设定和检查记录保存在当前站点的浏览器数据库。应用代码不发出模型请求或正文上传请求。不提供云同步，也不把本机数据库宣称为加密保险箱。
- 刷新保留已保存内容；清理站点数据、更换设备、资料或网址可能丢失访问。用 JSON 作品备份在设备间手动迁移；恢复时校验引文并创建独立副本。
- 导出 TXT 报告含成对原文与作者判断。项目删除前需要输入完整作品名。数据库写入有版本冲突检测，避免跨标签页静默覆盖。

## 可爱与互动

奶油色书桌、圆角纸片、彩色设定标签。小书灵“小章”为代码绘制的 SVG，会呼吸、眨眼、挥手，点击会轻跳并给出操作提示。流程书签支持直接跳转；批量确认设定和收录新章时出现纸屑庆祝。支持系统“减少动态效果”偏好，无背景音和远程图片。

## 本地运行

无需安装第三方依赖。使用本机静态 HTTP 服务，避免通过 file:// 打开 ES 模块：

```sh
python3 -m http.server 8080 --directory dist
```

然后访问 http://localhost:8080 。测试需要 Node.js 24：

```sh
npm test
npm run check
```

Windows 如使用 Python 启动器，也可以运行 `py -m http.server 8080 --directory dist`。请通过 HTTP 服务运行，直接双击 HTML 文件会受到浏览器 ES 模块限制。

`dist/` 是完整静态应用，可以部署到支持静态网站的托管服务。不同网址的浏览器数据相互独立，用 JSON 备份手动迁移。
