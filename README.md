# 章序 · Zhangxu

给中文连载作者的一张小书桌：**本地规则核对 + 可选 AI 语义审稿 + 新旧原文证据 + 作者判断**。

版本 **0.2.0**。规则检查免费、在浏览器运行；AI 审稿通过后端调用 DeepSeek 官方 API，需要可用的 API Key，费用由供应商按用量收取。当前没有平台收费、账号云同步或自动全书审稿。

![章序规则检查界面：合成稿中的成对原文证据](docs/preview.jpg)

## 开始使用

安装 Node.js 24，然后运行：

```sh
git clone https://github.com/beicheng007/zhangxu-continuity.git
cd zhangxu-continuity
npm start
```

打开 http://127.0.0.1:8080 。这个仓库的本地服务没有第三方运行依赖，无需 `npm install`。

1. 导入已写好的 TXT / Markdown / DOCX 旧稿，或载入测试样稿。
2. 规则提取的候选设定先由作者确认；AI 也可以直接对照旧稿，不要求先提取到规则事实。
3. 在“新章检查”填入新章，选择“本地规则检查”或“AI 语义审稿”。
4. AI 窗口会显示模型、发送范围和完整原文预览。在密码框中填写 **DeepSeek API Key**，确认发送内容与费用后开始。不要把密钥放进聊天、Issue 或 GitHub。
5. 核对成对引文，标记“确有错误”“正常变化”或“误报 / 不适用”，添加备注、导出报告，完成后收录新章。

API Key 可在 [DeepSeek 平台](https://platform.deepseek.com/)管理。默认 `deepseek-flash`，也可选择 `deepseek-v4-pro`。调用协议依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/)；模型可用性和费用以供应商账户为准。

也可以把服务器密钥配置在本机 `.env`：复制 `.env.example`，自行填入 `DEEPSEEK_API_KEY`，重启服务。`.env` 已被 Git 忽略。前端只能获知服务器是否配置了密钥，不能读取其值；不需要服务器密钥时留空，在页面按次提供即可。

## AI 审稿做了什么

- 从前文按字词重合、已确认对象和最近两章选择片段，加入相关已确认设定和别名，对照新章。尝试发现不同措辞中的能力、身份、关系、物品归属、事件衔接等疑点。
- 提示词要求先排除已有解释的正常变化、回忆、传闻、梦境、伪装和时间推进；这属于审稿策略，不能保证模型始终遵守。
- 每条 AI 疑点必须包含指定前文片段与新章中的逐字引文。服务器和浏览器各校验一次，拒绝改写、拼接、找不到、无法唯一定位或重复的引文。
- 合法引文只证明“原文确实存在”，**不能证明 AI 对它的理解正确**。结果统一标注“AI 疑点”，由作者判断，不自动修改正文或确认新设定。
- 每轮新章最多 **12,000 字符**，前文最多 **24,000 字符 / 40 个片段**，输出最多 **4,096 token / 10 项疑点**。发送前后均显示前文覆盖比例。未选前文不在本轮检查范围内，当前没有向量数据库或全书时间线。
- 每次确认只发起一次模型请求，不自动付费重试。报告保留供应商返回的输入、输出 token 数；没有返回则标明未知。停止等待不保证供应商取消计费。
- 密钥错误、余额不足、限流、网络错误、超时、空输出、拒绝或 JSON 截断会明确报错，不保存为成功的零疑点结果。剔除无效疑点时显示数量与结果不完整提示。

**验证状态：接口、证据校验和异常路径已自动测试；尚未配置真实 API Key，未完成真实 DeepSeek 推理验收。** 不宣称真实作者准确率、召回率、节时或付费效果。测试中的供应商响应为明确的测试夹具，不是模型实测。

## 规则检查与现有流程

支持 12 类明确设定：惯用手、瞳色、血型、生父、生母、出生地、年龄、阵营、生死状态、固定编制、长度、别名（用于归并对象）。例如“陆沉的惯用手是左手”“陆沉效忠北境军”。只识别有限句式，代词与隐含关系由可选 AI 尝试分析。

回忆、对话、传闻、梦境、伪装、明确变化和时间推进通过有限文本线索降低结论强度；年龄、阵营和生死状态的差异均交由作者判断。支持常见中文数词和同一度量体系的长度换算。

章节按导入、收录顺序排列，不自动推断故事时间。确认后的同一对象、同一属性以最近收录章节为准。收录新章产生的规则候选仍需确认。相同正文、标题、证据与设定上下文可恢复作者判断；改写后旧结果会提示重新检查。

[规则前文](examples/old-manuscript.txt) / [规则新章](examples/new-chapter.txt)：预期 3 条明确差异、4 条剧情提示。与用户稿件使用同一引擎，无预设结果。

[语义前文](examples/semantic-old.txt) / [语义新章](examples/semantic-new.txt)：人工预期只应提示已熔毁原钥匙再次出现；治愈后的视力恢复、退出阵营应视为已有解释的正常变化。这个预期用于后续真实模型验收，**尚未通过真实模型验证**。

## 稿件、密钥与备份

正文、设定、检查记录和作者判断保存在当前站点的浏览器 IndexedDB。导入、规则提取、规则检查不上传正文。换设备、浏览器资料或网址，以及清理站点数据可能丢失访问，请定期导出 JSON 作品备份；恢复时会逐字检查引文。

只有确认 AI 审稿后，新章、所选前文、相关确认设定与别名才经本服务转发给 **DeepSeek 官方接口**。本服务代码不持久化正文、密钥或模型响应，不记录请求正文，不把密钥返回给浏览器。供应商如何处理内容以其政策为准。页面填入的密钥只保留在当前标签页内存，刷新即清除，可手动清除；不进入 IndexedDB、localStorage、报告或作品备份。浏览器本地数据并不等于加密保险箱。

TXT 支持 UTF-8 / GB18030；DOCX 读取可编辑正文，不含扫描图片、页眉页脚或批注。单文件 8 MB，单次导入 150 万字符 / 1500 章，单部作品 300 万字符 / 3000 章，规则新章最多 10 万字符，最多 200 次检查记录。

## 部署与开发

`npm start` 默认仅监听本机 `127.0.0.1`。公开托管后端前，应另行配置访问控制、限流与个人用量额度；不要把使用共享付费密钥的裸接口直接对公网开放。本项目的现有线上工作台保持原有私有访问范围。

只想用本地规则时，也可把 `dist/` 作为静态网站部署。纯静态服务不支持 `/api/ai-config` 和 `/api/semantic`，AI 按钮会提示需要完整后端；把静态文件上传 GitHub 不等于拥有 AI 服务。

```sh
npm test
npm run check
```

- `dist/engine.js`：纯规则引擎；`dist/semantic.js`：检索、请求边界、引文校验与 AI 判断转换。
- `server/ai-service.mjs`：固定 DeepSeek 官方地址、请求限制、供应商响应处理，不接受自定义上游地址。
- `server.mjs`：零依赖本地 HTTP 服务；`dist/app.js`：界面与完整作者工作流。
- [QA.md](QA.md)：验证记录与限制；[CONTRIBUTING.md](CONTRIBUTING.md)：贡献说明。当前仓库未指定开源许可证。

小书灵“小章”、奶油色书桌和流程书签均由本地代码绘制，支持“减少动态效果”，无远程图片或背景音。
